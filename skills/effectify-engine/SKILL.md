# Improve the engine

Every facade in effectified/packages is a test of the engine: real libraries, each with its surface, recipe, generated package and behaviour tests. A gap one facade exposes is fixed here, never in a facade's generated code, and the other facades prove the fix breaks nothing.

## The standard

A facade is Effect-native, not Effect-wrapped: a user who knows Effect finds Effect's own vocabulary in every signature. The standard is pi-effect's (`effect/AGENTS.md` of effectified/pi, "Effect-native design"), held by the same tools: the Effect team's `@effect/tsgo` presets correctness, antipattern, strict and effect-native as errors (`missingPipeableSignature` and `missedPipeableOpportunity` off, with the reasons in `src/diagnostics.ts`; tests keep correctness and antipattern), run by tsrs, and the idiom rules of `src/idioms.ts`, run by oxlint. What it means for generated code and the runtime:

| Rule | What the engine writes |
|---|---|
| Functions | Every Effect of a facade is `Effect.fn("<Handle>.<method>")` (exports: their operation, `createTransport`, `new Queue`, `Runtime.create`): a span and a stack frame per call. A Stream gets `Stream.withSpan`, an event stream `<Handle>.events.<event>`, a release `<Handle>.<release>`. `recipe.untraced` names per-item hot paths (`Effect.fnUntraced`). |
| Errors | `Schema.TaggedError<Self, { readonly brand: unique symbol }>`, carrying only the fields upstream's error class declares (numbers `Schema.Finite`; any value but a primitive `Effectify.Sealed`, an identifier such as `code` as it is), built with `.make(..., Effectify.unchecked)` (upstream's values are never validated); upstream's failure is never copied or walked, only kept as the cause, `Effectify.Sealed`: a `Redacted` printed nowhere, reached with `Redacted.value(error.cause)`, and encoded to canonical JSON as the marker `"<redacted>"` (never `Schema.Redacted`, whose JSON codec writes the value out). A synchronous method's throw goes through the same `classify` and is thrown as the facade's error; a stream fails with every failure of its iteration classified the same way: its call or its iterable's `[Symbol.asyncIterator]()` throwing as it starts, a step that throws or rejects, a step whose result throws as it is read (the runtime reads it, once, not `Stream.fromAsyncIterable`), an iterator whose `return` throws as it is read (read once, as it starts) fails it, and a `return()` that fails as it ends dies of its failure classified. The generated `classify` takes the call's secrets and scrubs the message (`describe`) and each declared string field (`scrubbed`) of them; a member of upstream's failure that throws as it is read makes a failure that could not be read, never a defect. An error with codes has a `reason` tagged union of them (`Effect.catchReason`), with a case for any other code when it is also reached without one (the catch-all, an upstream class), named the first of `Other`, `Unlisted`, `Unlisted2`, `Unlisted3`, ... that is no upstream code (`fallbackReason`). `Failure` is `Schema.Union([...]).pipe(Schema.toTaggedUnion("_tag"))`: `.match`, `.guards`, `.isAnyOf`. |
| Absent values | An async method or export whose value may be absent in every kept overload (`T \| null`, `T \| undefined`, read from the printed type) resolves to an `Option`, of the facade when the present part is a handle. `<Handle>Optional` lists them; `OptionSpec` checks each against upstream's types. Sync calls and properties stay as upstream types them, but a synchronous method's handle that may be absent is its facade or the absence (`ElementHandle.asElement()`), as is one an async overload that is no `Option` resolves to (`Effectify.Lift`, `Effectify.Resolved`). |
| Secrets | `recipe.secrets` (`<call>` -> `<index>.<property>...`): the parameter types take `Redacted` too (`Effectify.Redacting`), the runtime reveals each in the call. Each secret is read once, at the call, from the copy the reveal makes: the value scrubbed is the value sent. Every property read through and every method's result that is no handle show each secret path past its index as `Redacted` again wherever a plain object in them has it, at any depth (`Concealed`, `Effectify.ConcealedIn`), in one walk over plain objects and arrays that copies each once (cycles and shared branches kept); any other value is kept as it is, or `Redacted` where a path ends at it. A value keeping a secret in another shape is a recipe `exclude`. Every failure of a call given a secret, and of the handles it made, has its message and declared string fields scrubbed of each secret of four characters or more (`SECRET_LENGTH`: a shorter one matches ordinary text, `A` in `EAUTH`, more often than it echoes the secret); codes never. A facade prints, serialises and inspects as `{ _id: "<Handle>" }`, its `upstream` not enumerable; upstream's `toJSON` and `toString` are never wrapped in a runtime facade (`ownMembers`). Known escapes, upstream's own and documented next to `upstream` in the runtime: `facade.upstream`, and upstream's code (a logger, a plugin). |
| Ownership | A method returning a releasable handle owns it: an Effect acquires it in the caller's scope, a synchronous call hands over its facade with its release methods. `recipe.borrowed` names the methods returning one upstream already holds (a lookup, the receiver itself, a handle the receiver holds), wrapped, never released, no `Scope` (`Effectify.Borrowed`); without a list the rule decides (`borrowedByRule` in `src/methods.ts`, which the draft writes into the recipe for a person to confirm), and a list, empty too, wins over it both ways; the rule leaves a synchronous copy (`clone`, `copy`, `duplicate`) owned. A property's handle is always borrowed, and so is each handle of an array a synchronous call or a property gives (`HandleSpec.lists`, `listedHandles` in `src/methods.ts`; `Effectify.Listed`). An async method's array follows the rule for one handle: a list it makes (puppeteer's `$$`) is the caller's, each handle acquired in its scope (`Effectify.ResolvedList`), and `borrowed` or the rule (`borrowedMethods`) names one it finds (`Browser.pages()`). `Handles` names each releasable handle's release methods (`releaseMethods`) that a borrowed facade leaves out, in its type (`Effectify.BorrowedFacade`) and at run time: a handle a property holds needs its release declared. Every release the analyzer reads (`Handle.releases`) and the draft offers (`draftReleases` in `src/recipe.ts`) passes one rule, `isRelease` in `src/surface.ts`: named so (`RELEASE_NAMES`, in the draft's order of preference) and callable as the scope's finalizer calls it, with no argument (a trailing callback it reports through aside, which the runtime gives), whatever it gives, as 0.3.0 had it. Where the types cannot decide, the engine does as 0.3.0 did: a borrowed facade hides a release only when the types make it certain the method is no step of a traversal, by one rule, `hiddenWhenBorrowed` in `src/methods.ts`, which the generator (the `Handles` entry; `HandleKind.kept`, from `keptReleases`) and the draft's reasons read: every signature gives no handle of the surface (void, a boolean, a promise of those, any value the facade gives as it is) or gives its receiver as upstream declares it (`this`, or a promise of it: Node's `Server.close(): this`). A release whose result names a handle by its class stays on a borrowed facade (`HandleKind.kept`), as every release did in 0.3.0: zmq's `Socket.close(): Socket` (@types/zmq, a hand-written `.d.ts`) closes the socket and returns it, cheerio's `end(): Cheerio<AnyNode>` steps back to the selection before the last `find`, the types cannot tell the two apart, and hiding a step would break every traversal through a borrowed handle. Only the declaration tells the receiver: the checker prints `this` as the handle's own type through a generic handle or one that inherits the method (chart.js's `Chart.stop(): this` is `Chart<TType, TData, TLabel>`), so the analyzer reads the declared signature's result (`Signature.receiver`), never the printed type or the name. A name that also means something else is never offered, since the finalizer would destroy what the program holds (postcss's `Node.remove()` takes a node out of its tree, protobuf.js's `remove(object)` takes the child it is given), nor a release that takes an argument (chart.js's `Animator.stop(chart)`): a release under another name (MapLibre's `Map.remove`, puppeteer's `CDPSession.detach`) is a person's decision in the recipe. Calling upstream and giving what it gives an owner are one step (`call`), uninterruptible from just before the call until a value is handed to the caller (`handedOver`) or a promise has, in that same synchronous step, the handler its settlement is read from (which `settle` awaits): an interruption requested as the call runs (upstream aborting its caller), or one that comes while the fiber yields to the scheduler, waits until then, so nothing upstream gives is left to nobody, and no rejection goes unhandled. Every acquisition takes that path: an async method's, a list's, an exported function's, a constructor's, and a call's that reports through its callback, whose report is the promise (`reporting`). An interruption lands only while the call waits for upstream to settle, and what it does there is decided once per method from its spec (`Handing`, from `handing`), never per call: it aborts upstream's signal at once, and a call that gives no releasable kind (a value, a borrowed handle, a kind with no release) is left to itself, the interruption completing at once, but an acquisition (`Acquired`: a call whose `returns`, `choices`, `lists`, absent value or `mixed` result, exported function, constructor or callback method may give a releasable kind) follows Effect's `acquireRelease`, as 0.3.0 did: the interruption's finalizer, uninterruptible, waits for the call to settle and leaves what it gave to the scope (`leftToScope`), each releasable handle handed over as a call that was not interrupted hands it (`handedToScope`: its finalizer registered, the lease respected), and the scope releases it as it closes, in the scope's order (at once when the scope closed already: Effect's `Scope.addFinalizer` runs a finalizer added to a closed scope), so when the interrupter resumes nothing of the call still runs and nothing it gave is left without an owner. Earlier 0.4.0 candidates returned at once and released a late handle in a fiber of its own ("late cleanup"), which raced the scope's finalizers, then released what the call gave before the interruption completed, which deadlocked a listener whose `close()` waits for a peer connection the caller cleans up only once the interruption returned. A non-releasable call pays nothing for this: the same abort it always had. The release is registered before the handle is wrapped. The scope releases what it acquired when it closes, whatever the user did with it, as Effect's `acquireRelease` does and as 0.3.0 did. A user's call of a release method (the recipe's `release`, `disconnect`, `detach`) never reads or changes the lease: it reaches upstream and gives its own value, wrapped by that call, as every other call does, so a release called twice, or through another facade of the object, runs twice, and the scope's release as it closes is one more call. Were a user's call to mark the lease, the scope would skip what the user released and wait for what the user is releasing: a listener closed through its facade and started again would outlive its scope, and the scope's finalizer, waiting for a user's `shutdown()` still running, would hang when that shutdown waits for a connection only a later finalizer of the scope closes. The lease (`Lease`, shared by every acquisition of one object in a scope, `leasesOf`) only keeps the engine from releasing an object twice: the scope's finalizers, a list holding one handle twice and two acquisitions of one object call its release once between them. Its state (`LeaseState`) is `Open`, `Releasing` (an engine release runs) or `Released` (one succeeded, in its form: a synchronous release returned, a promise resolved, a callback reported no error). The first engine release (`releaseOnce`) reads the lease and marks it `Releasing` in one synchronous step, before its fiber can yield, then calls upstream in the release's form (a callback release is given one); any other engine release of the object skips at once and never waits, so no release can wait on another that waits on it; one that fails, or is interrupted before upstream reported, reopens the lease, so a later engine release may try again. A failed engine release is logged as a warning (`<Handle>.<release> failed while its scope closed`, the facade's error as its cause) and never fails the scope's closing: it is often a second call after the user's own. An acquisition, interrupted or not, registers a finalizer for every handle of a releasable kind whose lease no finalizer of the scope releases yet (`Lease.scoped`), claimed in the step that finds it unclaimed, so an object gets one finalizer in a scope however many acquisitions give it; a kind with no release (a choice's) claims no lease, so a later acquisition of the object as a releasable kind registers its finalizer. A result that is one of several handles by the call's type arguments (puppeteer's `HandleFor<T>`: `ElementHandle` or `JSHandle`) is read by the analyzer from the conditional's branches (`Signature.handles`), listed in `HandleSpec.choices` (the handle with the most methods first), and wrapped as the first whose methods the value has, owned or borrowed as one handle is. |
| Re-exports | Upstream's values that need no wrapping are re-exported by name, but never one the surface marks `erased`: Node could not import it, and the facade would fail as it loads. A name that is no identifier (ES2022's `export { x as "review-sentinel" }`) is written as its string wherever one may stand: a re-export, `Upstream["review-sentinel"]`, a key; an export named so is never wrapped (`wrappedExports`: a wrapper is a declaration named after it), and `reconcile` notes one a recipe offers (`unwrappedNote`). A key of an object literal made at run time is never a bare or quoted `__proto__`, which sets the prototype: it is computed, `["__proto__"]` (`ownKey`). Only a surface `study` wrote with `runtime: "imported"` says which those are (`valueExports`): from one studied before 0.4.0 the facade re-exports no value, as 0.3.0's did, and `reconcile` prints a note naming the values it leaves out, of which `study` finds those Node can import (`restudyNote`). |
| Brands | `recipe.brands` (`JobId` -> `Job.id`, `Queue.getJob(0)`, `Mail.sendMail().messageId`; drafted from a handle's string `id` and `<handle>Id` parameters): `<Brand> = Schema.String.pipe(Schema.brand(...))` exported, properties `Effectify.Branded`, parameters `Effectify.Branding`, results `Effectify.ResolvingBranded`; types only. Secrets and brands are one type rewrite (`Effectify.Rewritten`, `src/rewrites.ts`), and `CheckedPlaces` fails to compile on a place that is no string in upstream's types. |
| Streams | Event emitters through `Stream.callback`, an explicit buffer (`EventOptions`: unbounded by default, since an emitter cannot be paused). |
| Traits | A facade is `Equal` and hashes by its upstream object's identity (`Hash.random`). |
| Services | `Context.Service` with `layer` for every handle the recipe lists, releasable or not. |
| JSON | Through Schema, generated tests included (`Schema.fromJsonString`). |
| Data | Upstream's types stay upstream's (re-exported, derived); the engine restates none by hand. |

Left out on purpose, with the reason: Schemas of upstream's options and results (the engine has no type-to-Schema compiler, and a hand-written mirror is what the standard forbids); `Match` and dual APIs in generated code (it chooses over no union, and a facade method keeps upstream's shape); caching and batching (a facade adds no behaviour, and no upstream call is deterministic enough to cache for the user).

## Rules the engine keeps

- The facade's types are the compiler's: where the analyzer and upstream's types disagree, `reconcile` records an override and the runtime follows the types. Never make the runtime guess at run time what the types decided.
- Generated output is deterministic: `test/engine.test.ts` regenerates the `src/index.ts` of every fixture in `test/fixtures` and compares bytes; effectified/packages' CI does the same for every facade it keeps.
- What every member of every handle gives has one source, its spec: whether its value is wrapped (`returns`, `choices`, `lists`, a property holding a handle) is the generator's reading of upstream's text, and the facade's types follow it. A member the spec gives as it is is typed as upstream declares it (`<Handle>Facades`, `Effectified`'s `G`; `never` handles in a written-out or lifted signature), whatever handle its value is to the checker: an inline `Base | Derived` and its promise, a generic result such as ts-morph's `asKind` (`KindToNodeMappings[TKind] | undefined`), a property such as its `compilerNode`. So the types cannot show a facade the runtime does not give. The other way, a member the spec wraps that its type would show raw, is a generator bug, and the check catches it: what every member gives agrees between its facade's type and its spec (`CheckedGives`, `Effectify.Disagreeing`): raw, a facade owned or borrowed, a list, an `Option`, a `Stream`. A method whose overloads give its handle in some calls and no handle by their text in others (cheerio's `html()` reads a string, `html(value)` sets it and returns the selection, `attr()` reads a record) is `mixed`: each overload is typed by its own result, the check takes either word for each, and the runtime wraps a result only when it has every method of the handle upstream does not declare optional (`HandleSpec.required`, from the surface's `Handle.optional`: a `refresh?()` it may lack; a handle whose methods are all optional wraps any object; written only when some are, and checked against upstream's types, `Effectify.RequiredMethods`) (a structural check, as the overload's type is one; a generic overload whose value is a handle, ts-morph's `getFirstAncestor<T extends Node>()`, is wrapped too, so identity with the receiver would not do), any other value as it is. No other mix is wrapped: a method whose overloads give one handle or a list of it (ts-morph's `addExtends(text)` and `addExtends(texts)`), or a list or another value (`EnumDeclaration.addMembers`: `EnumMember[]` or `(CommentEnumMember | EnumMember)[]`), gives its value as it is, typed so (`returnedHandles`, `listedHandles`). The analyzer names a handle by its type's name, so one name is one type (`SurfaceReader.symbols`): another type of a name already read (the compiler's `ts.ClassDeclaration` in ts-morph's `compilerNode`, protobuf.js's `rpc.Service` beside its reflection `Service`, engine.io's `Socket` beside socket.io's) is no handle. A method's facade overloads are intersected one by one (`EveryOverload`), never by `UnionToIntersection`, whose inference compares the overloads with each other, so the facades their parameters take, which can lead back to the member being typed (ts-morph's `Directory.getRelativePathTo(sourceFile | directory)`): TS2615 at every use. A method that only throws (`never`, commander's `error()`) agrees with any word. A member whose type says otherwise than the runtime does fails to compile, by name; every overload of an overloaded method is read, and a lifted method as `Effectify.LiftedResult`. Every overload of a method the spec runs as an Effect is typed as one (`ScreenRecording.pipe`'s overload that returns its destination), and a method whose signatures the checker cannot split (`Overloads` is `never`, puppeteer's generic `toElement`) is read from its one signature. A union of sibling handles (postcss's `ChildNode`: `AtRule | Rule | Declaration | Comment`, each a `Node`), alone, optional or in an array, is raw on both sides: the generator reads one handle's name (`namedHandle`) or a conditional's choice, never a union, and the types, where a member's spec wraps it, take a union for a handle only when one of its members is all of them, or is itself a handle all of them are (`HandleOf`, `IsOneHandle`: puppeteer's `HandleFor<Element | null>`, an `ElementHandle<Element> | JSHandle<null>`, is a `JSHandle`). Telling the siblings apart at run time would take their classes (`instanceof`), which a second copy of upstream, a plugin's own, defeats.
- Every handle spec `satisfies` what upstream's types say (`AsyncSpec`, `StreamSpec`, `OptionSpec`, the method and property lists), and every secret and brand place is checked (`CheckedPlaces`), so drift is a compile error, not a run-time surprise.
- Generated code and the runtimes hold to the standard: `test/engine.test.ts` runs the idioms over every fixture's generated sources and both runtimes, and the Effect rules over the runtimes; `reconcile` and `verify` run both over every facade. A rule that must stay off for facades is an entry of `src/diagnostics.ts` with its reason; a site that must break an idiom says why in the comment lines right above it (`// idiom-allow <rule>: <why>`, `<rule>` one of `src/idioms.ts`: `effect-fn`, `effect-fn-arrow`, `effect-fn-name`, `match`, `branded-id`). A syntax rule sees no types, so `match` takes a choice over a tagged union by how one is written: a `switch` whose discriminant reads `_tag`, Effect's tag (`x._tag`, `x?._tag`, `x["_tag"]`, `x!._tag`, `x._tag as T`, `<T>x._tag`); a `switch` on any other field (`.type`, `.kind`, an HTTP response's numeric `.status`), a number or a string is left alone, since it is as often no choice over a union.
- Use only Effect 4 APIs you have read in `node_modules/effect/dist/*.d.ts`; TypeScript 7's API is `unstable`: check `node_modules/typescript/dist/api/sync/api.d.ts`, and guard what can panic (`getAliasedSymbol` on a non-alias, printing some nodes).
- No install scripts, exact versions, and nothing newer than the machine's release-age policy.

## A fix, step by step

1. Reproduce on the facade that showed it, from a checkout of effectified/packages next to this one: `node ../engine/src/bin.ts reconcile <name>` runs this checkout's engine on that repository's `targets/`. Reduce it to a unit test where you can (`test/engine.test.ts`, `test/runtime.test.ts`: the runtime's type rules are tested with `expectTypeOf` and `@ts-expect-error`).
2. Fix the engine.
3. Regenerate, test and verify every facade with this checkout, from the packages checkout: `for t in $(ls targets); do node ../engine/src/bin.ts reconcile $t && node ../engine/src/bin.ts test $t && node ../engine/src/bin.ts verify $t; done` with the services up (Redis on `REDIS_URL`, Chrome on `CHROME_BIN`); `verify` builds each release and imports every entry point in Node. `reconcile` ends with the standard's checks (`EffectNativeError` lists each finding as `effect|idioms file:line:col rule`): fix the generator or the runtime, or a hand-written test or mount, never a generated file. "TypeScript 7.1 notes" after it fail nothing: they are where tsrs and tsc 7.0.2 disagree. `git diff targets` there is what the change does to every facade. An analyzer change reaches a facade only through `study <npm name>@<version>`, which rewrites its `surface.json`: copy it to the fixture too.
4. Here: copy changed recipes and surfaces of fixture targets into `test/fixtures/<name>/`, `pnpm test -u` if the fixtures changed as intended, then `pnpm check && pnpm test && pnpm build` (`pnpm check` holds the engine's own code to its types and the Effect rules of its tsconfig.json in one tsrs pass, then oxfmt and oxlint; `pnpm build` compiles `src/` with tsc 7.0.2; `pnpm format` writes the formatting; never run oxfmt on `src/runtime/` or `test/fixtures/`, which facades and the generator's tests compare byte for byte). Raise the version (`package.json`, `ENGINE_VERSION`) when facades change, and commit. Before a release, run `pnpm corpus` (`scripts/corpus.ts`): it makes and verifies a list of popular libraries that are no target with the released engine and with this checkout, and fails on one the released engine passes and the checkout fails, unless its entry names the changelog's announced change: the step it fails in and what that step prints (`announced`), any other failure being a regression. A step passes only with evidence that it finished, not on an exit with 0 alone: the engine's own last line for `make` and `verify`, and for a library's program (`scripts/corpus/<name>.ts`, run after `verify`) a whole line of its stdout, `USE_FINISHED` and the token the corpus makes for that run and gives it in `TOKEN_VARIABLE`, which it prints as its last act: what the library prints, `corpus: finished` too, passes nothing.
5. Once the engine is released, in effectified/packages: move `@effectified/engine` to the new release, commit the regenerated facades with it (a changed released facade also gets a new `recipe.revision`, which moves its npm version, with a decision `revision` saying what changed), and open one pull request.
